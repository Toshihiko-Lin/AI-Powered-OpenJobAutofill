# AI-Powered OpenJobAutofill

[English README](README.en.md)

这是我在 [Br1an67/OpenJobAutofill](https://github.com/Br1an67/OpenJobAutofill) 基础上继续开发的网申填写扩展。上游把"本地规则 + 可选 AI 理解页面字段"这条路走通了，简历数据留在本机，AI 只看字段名。我沿着这个思路把 AI 用到了另外两头：**把简历读进资料库**，以及**把你在网申页面上手填的内容学回资料库**。

所以现在它是一个闭环：

1. **上传简历自动解析** —— 把 PDF / DOCX 简历丢进去，AI 拆成资料模块，不用逐项手填。
2. **一键填写网申** —— 打开招聘网站点 `开始填写`，能确定的字段填好，其余标出来。
3. **从修改中更新资料库** —— 网申页面上你改过、补填过的字段，勾选一下写回本机资料，下一家就能自动填。

秋招要填几十份网申，每一份都有几个资料库里没有的字段。这个闭环的意义就是：填过一次的东西，不该再填第二次。

## 功能一览

- 一键扫描当前招聘页面，自动填写能确定的字段，其余标为待处理。
- 简历资料只保存在本机浏览器，不上传云端。
- 上传 PDF / DOCX / TXT / MD 简历，由 AI 解析成资料模块。
- 填写后在网页上修改或补填的字段，一键写回资料库，越用越准。
- 支持常见输入框、文本域、单选、多选、下拉框和日期类字段。
- 资料面板可以按分类查看、搜索、复制内容，处理待处理字段。
- 可选接入 OpenAI 兼容 API 或自定义 API。
- 页面用三种标记反馈结果：绿色已填写、橙色待处理、橙色虚线资料库缺失。
- 支持检查 GitHub Release 更新，有新版本时图标显示 `NEW`。

## 安装

支持以开发者模式安装到 Brave、Chrome 或 Firefox（140 及以上）。不需要安装依赖，不需要构建，加载项目目录即可。

### Brave / Chrome

1. 克隆或下载本仓库：`git clone https://github.com/Toshihiko-Lin/AI-Powered-OpenJobAutofill`
2. 打开 `brave://extensions/` 或 `chrome://extensions/`，开启 `Developer mode`。
3. 点击 `Load unpacked`，选择项目目录。
4. 固定扩展图标。

### Firefox

1. 克隆或下载本仓库。
2. 打开 `about:debugging#/runtime/this-firefox`，点击 `临时载入附加组件…`，选择 `manifest.json`。
3. 在工具栏扩展菜单中固定图标。

Firefox 注意事项：

- 临时载入的扩展关闭 Firefox 后会被移除，重启后需要重新载入；已保存的资料仍在扩展存储里。
- 重新载入扩展后，请**刷新**已打开的招聘页面再点"开始填写"，否则旧的内容脚本还挂在页面上。
- Firefox 不会自动授予 `api.github.com` 访问权限，需要检查更新时在 `about:addons` → 权限里开启。
- 配置 AI 接口后第一次调用会弹出站点授权提示，允许后才能请求。

## 第一次使用

1. 点击扩展图标 → `设置`。
2. 建资料库，三种方式任选：
   - **上传简历自动解析**（推荐）：先在下方填好 API 设置，再点简历资料上方的 `上传简历自动解析`，选 PDF / DOCX 文件。
   - 导入 `sample-profile.json` 先试效果。
   - 按模块手动填写。
3. 逐项检查后点 `保存资料`。
4. 打开招聘网站的填写页，点扩展图标 → `开始填写`。
5. 看页面标记：绿色已填，橙色待处理，橙色虚线是资料库里没有的字段，手填。
6. 填完这一页，右下角浮层会提示 `N 处修改 · 点击更新资料库`，勾选写回。
7. 自己确认页面内容后提交。多页表单每进一步再点一次 `开始填写`。

## 上传简历自动解析

- 文字提取在本机完成：PDF 用内置 pdf.js，DOCX 用浏览器原生解压，不依赖任何在线服务。扫描件 / 纯图片 PDF 提不出文字，请用 DOCX 或文本。
- 点击后会弹确认框，写明文件名、字数、发送目标。**这一步会把简历全文发给你配置的 API**，和"AI 不接收简历具体值"的默认边界不同，确认后才继续。
- 默认只填写空字段，已有内容的经历模块不动；勾选 `覆盖已有值` 可整体替换。
- 结果只写入编辑区，检查后点 `保存资料` 才落盘。时间、学历、学位这些字段建议重点复核。

## 从网申修改中更新资料库

点击 `开始填写` 之后，页面上的改动会被记录（默认开启，可在设置页"偏好设置"关闭）：

- 浮层显示 `N 处修改 · 点击更新资料库`；弹窗里也有 `更新资料库` 按钮，关掉自动记录时可以手动对比一次。
- 面板里每条标明去向：
  - **更新**：你改了已自动填写的值，比如换了手机号 → 更新对应资料项。
  - **新增**：你补填了资料库里没有的字段，比如学号 → 写入对应模块；经历类会让你选第几条，或新增一条。
  - **同义字段**：你填的值和资料里某个字段的值一样，只是这个网站叫法不同（"毕业学府" vs "学校"）→ 记住这个叫法，下次直接匹配，不新增重复字段。
  - **自定义字段**：页面字段名对不上任何标准字段 → 手动选模块，或点 `AI 归类未匹配项`（只发送字段名，不发送值）。
- 只是格式差异的改动（日期写法、下拉选项文案）会自动忽略。
- 勾选后点 `写入资料库` 才保存。未处理的记录跨页面暂存，下一步表单里还能看到；设置页可一键清空。

## AI 设置

AI 是可选的。不配置 API 时，一键填写仍用本地规则；简历解析和 AI 归类需要 API。

支持 OpenAI 兼容接口（Base URL + 接口路径 + 模型名），也支持自定义请求模板。设置页有 `测试 API 连接` 和 `刷新候选模型`，模型名可以手动输入。

**隐私边界**：一键填写和 AI 归类的请求只包含页面字段名和本机资料的字段名，不含姓名、手机号、证件号、经历内容等值；取值和填写在本机完成。唯一例外是上传简历解析，它必须把简历全文发给模型，因此每次都会单独确认。

## 更新

扩展会定期检查本仓库的 GitHub Release，也可以在弹窗或设置页手动 `检查更新`。有新版本时图标显示 `NEW`，点 `打开 Release 页面` 下载后覆盖或重新载入。

更新前建议先 `导出资料备份`。不要先卸载扩展，覆盖或重新载入后本机资料和 API 设置会保留。

## 颜色标记

- 绿色：已填写。
- 橙色：待处理，资料里有匹配项但没能自动填进去，需要手动处理或复核。
- 橙色虚线：资料库里没有这个字段，需要手填；填好后通过"更新资料库"写回，下次就能自动填。

## 隐私说明

- 简历资料和 API Key 只保存在本机扩展存储。
- 页面脚本只在你点击扩展并操作当前页面后注入。
- 不会自动点击最终提交按钮。
- 一键填写、AI 归类不发送简历具体值；上传简历解析会在确认后发送简历全文到你自己配置的 API。
- "更新资料库"记录的值只在本机，写入前必须逐项勾选确认。
- 检查更新只访问本仓库的 GitHub Release。
- 自动填写后仍请人工复核，尤其是证件、联系方式、日期、选择题和声明类字段。

## 常见问题

### 点击开始填写没有反应，或提示 Receiving end does not exist

刷新目标页面，重新打开扩展弹窗。Firefox 下重新载入扩展后必须刷新已打开的页面。仍无效就到扩展管理页重载扩展。

### 为什么有些下拉框或日期填不进去

招聘系统的控件实现差异很大，复杂组件会进入待处理状态。可以用资料面板搜索并手动选择；某类网站经常这样的话欢迎提 Issue。

### 上传简历解析失败或提取不到文字

先确认 `测试 API 连接` 能通过。扫描件 PDF 提不出文字，改用 DOCX 或文本；旧版 `.doc` 先另存为 `.docx`。模型返回无法解析时换个模型或开启 `response_format` 再试。

### 更新资料库面板里没有我改的字段

它只记录点击 `开始填写` 之后的改动，且不记录复选框 / 单选框。改完没出现的话，点弹窗里的 `更新资料库` 强制对比一次。

### 如何备份、迁移或清空资料

设置页 `导出资料备份` / `导入资料备份`；`清空资料和 API 设置` 会删除本机全部数据。
